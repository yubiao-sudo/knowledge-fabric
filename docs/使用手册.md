# Knowledge Fabric 使用手册

面向**使用者**（不必懂工程细节）：从启动服务 → 上传文档 → 检索问答 → 读懂结果，
一份文档走完。

> 项目根目录：`F:\knowledge-fabric`
> 设计规格与实现状态见 [README.md](../README.md)；本手册只讲「怎么用」。

---

## 1. 它是什么

一套**企业级 RAG 知识底座**。你把公司的文档（**PDF / Markdown**）放进去，它就变成一个专属知识库，
之后用自然语言提问，它会把**原文证据**（带页码、字符区间、来源文件）交给你或你的
Agent 产品，而不是给你一段无法核实的「AI 编的话」。

**支持一次摄入一个文件，也支持直接给一个文件夹让系统逐个读完**（见 §4.4）。

三种用法（按上手难度排序）：

| 方式 | 适合谁 | 入口 |
|---|---|---|
| **Web 控制台**（推荐） | 所有人 | 双击 `console\index.html` |
| **HTTP 接口** | 会调 API 的人 | `POST /v1/ingest`、`POST /v1/ingest-dir`、`POST /v1/search` |
| **网关 MCP / REST** | Agent 产品接入 | `mcp` / `POST localhost:8000/v1/retrieve` |

## 2. 启动（本机 Windows cmd）

**命令里不要带 `#` 注释**——cmd 会把 `#` 后面的内容当成命令参数。

### 2.1 基础设施（Postgres + Qdrant）

```bat
cd /d F:\knowledge-fabric
docker compose up -d postgres qdrant
docker compose ps
```

确认 `kf-postgres` 与 `kf-qdrant` 都显示 `Up (healthy)`。

> 端口说明：Postgres 用 **15432**、Qdrant 用 **6333**（已错开本机原生安装的 5432）。

### 2.2 三个服务（各开一个新终端窗口）

**终端 A —— 摄入服务（8083）**

```bat
cd /d F:\knowledge-fabric
set PYTHONPATH=F:\knowledge-fabric\services\ingest
set QDRANT_URL=http://localhost:6333
set DATABASE_URL=postgresql://kf:kf_dev_password@localhost:15432/knowledge_fabric
python -m uvicorn kf_ingest.app:app --port 8083
```

**终端 B —— 检索服务（8082）**

```bat
cd /d F:\knowledge-fabric
set PYTHONPATH=F:\knowledge-fabric\services\retrieve
set QDRANT_URL=http://localhost:6333
set DATABASE_APP_URL=postgresql://kf_app:kf_app_password@localhost:15432/knowledge_fabric
set AGENTIC_MAX_ROUNDS=3
python -m uvicorn kf_retrieve.app:app --port 8082
```

**终端 C —— 决策服务（8090，Laya 真权重，离线复用缓存）**

```bat
cd /d F:\knowledge-fabric
set PYTHONPATH=F:\knowledge-fabric\services\decision
set LAYA_CACHE_DIR=E:\Program Files\Laya\hf_home
set LAYA_SUBFOLDER=typed-decisions
set LAYA_SUBFOLDER_MULTILINGUAL=multilingual
set DECISION_TIMEOUT_MS=5000
python -m uvicorn app:app --port 8090
```

> 决策服务**冷启动加载 Laya 权重约 3 分钟**（CPU）。启动日志出现
> `Laya checkpoint 就绪: typed-decisions` / `multilingual` 才算就绪；
> 未就绪前链路仍可用（自动走规则回退），只是不体现模型判定。

### 2.3 打开客户端

直接**双击** `F:\knowledge-fabric\console\index.html` 即可（单文件、零依赖、不联网）。

若浏览器因安全策略拦截本地文件，可改为启动一个静态服务后用 `http://` 打开：

```bat
cd /d F:\knowledge-fabric\console
python -m http.server 8099
```

然后浏览器访问 `http://127.0.0.1:8099/index.html`。

## 4. 控制台三个页签怎么用

打开后顶部先确认：**摄入服务地址**（默认 `http://127.0.0.1:8083`）、
**检索服务地址**（默认 `http://127.0.0.1:8082`）、**租户 tenant / 知识库 kb**
（默认 `acme` / `demo`）。这些会记在浏览器 localStorage，下次自动带出。

### 4.1 页签「摄入文档」——把 PDF / Markdown 变成知识库

**方式一：上传单个文件**

1. 把文件**拖进虚线框**，或点击选择文件。
   支持 **`.pdf`** 与 **`.md` / `.markdown` / `.mdown`**。
2. 填/核对字段：

   | 字段 | 说明 | 建议 |
   |---|---|---|
   | `doc_id` | 文档标识（同一 doc_id 再传不同 `version` = 版本升级） | 如 `manual_v1` |
   | `version` | 版本号，整数 | 首次填 `1` |
   | `lang` | 文档语言 | 中文填 `zh` |
   | `doc-type` | 文档类型 | 手册选 `manual` |
   | `strategy` | 切片策略（语义断点 / 条款原子 / 代码语法 / 页级视觉等） | 不确定就留默认 |
   | `dry-run` | **只预览切片，不落库、不触网** | 首次建议先勾上试一次 |
   | `enrich` | 生成类增强（需要 vLLM，缺失会自动跳过） | 无 vLLM 时勾不勾都一样 |
   | `graph` | 建图 GraphRAG（同时开启该库的图检索） | 需要「跨文档汇总/关系」类问答时才勾 |
   | `acl` | 块级访问控制，逗号分隔，如 `user:alice,group:eng,!user:u9`；**留空 = 公开** | 不需要就留空 |

3. 点「上传并摄入」。
4. 看结果：会显示**切片统计**（块数、策略、耗时）与**落库结果**
   （Qdrant 写入点数 / Postgres 写入行数）。勾了 `dry-run` 则只有切片统计、无落库。

> 想先粗糙试一次？勾上 `dry-run` 直接传，看切出来的块长什么样，再决定要不要正式摄入。

**Markdown 文件的两点如实说明**（不是故障）：

- Markdown **没有「页」的概念**，所以证据卡片上的页码一律显示 `第 0 页`，
  摄入摘要里也会记一条警告 `no_page_layout`。定位仍靠**字符区间 + 来源文件**，精度不受影响。
- Markdown 的**表格**与**围栏代码块**会被当作**原子块**（整块不切开），
  `#`~`######` 标题会进入章节路径——这与 PDF 的结构化处理一致。

### 4.2 页签「文档库」——看里面到底有什么

点「刷新」，列出当前 `租户 / 库` 下的所有文档：

- `doc_id`、`title`、`lang`、`current_version`
- **`active_chunks`**：**当前版本的活跃块数**——这是「真的有数据可检索」的依据
- 版本老块的 `stale` 不计入

**检索命中为空时，先来这里确认：文档在不在？块数是不是 0？租户/库对不对？**

### 4.3 页签「检索问答」——提问并看证据

1. 填问题（如「产品交付后的保修期是多久？」）。
2. **检索档位**：下拉框内容读自服务端 `/v1/profiles`，默认 `hybrid_rerank`。
   不确定就留默认。
3. `top-k`（取前多少条证据，默认 10）、`max_context_tokens`（上下文预算，默认 8000）。
4. **访问主体 principal**（可选）：按 `type:id` 逗号分隔，如 `user:alice,group:eng`。
   **留空 = 不做 ACL 过滤**。用于测试块级权限是否生效。
5. **graph_enabled**（可选）：勾上才走 Graph 通道（前提是摄入时勾过「建图」）。
6. 点「检索」。

### 4.4 批量摄入一个文件夹

**方式一：控制台里的「目录批量摄入」区块**（推荐，不用敲命令）

在「摄入文档」页签下方，有一个独立的**目录批量摄入**区块：

1. **目录路径**：填**服务端本机**的文件夹路径，如 `E:\Users\OMEN\Desktop\文档`。
   （注意：这是「让服务去读这个文件夹」，不是上传文件——所以路径要是**跑摄入服务那台机器**上的路径。）
2. **文件名过滤**（可选）：只处理文件名包含该子串的文件，如 `技术完善`。
   **先小范围试跑**，避免把隐私文件一次全灌进去。
3. **递归子目录**（可选）：勾上才会往子目录里扫，默认只扫顶层。
4. **只预览切片 dry-run**（可选）：勾上则不落库，只出报告。**建议先勾一次看报告**。
5. 点「扫描目录并批量摄入」。

结果区会给出四张统计卡（**扫描到受支持文档 / 成功 / 失败 / 跳过**）、
每篇文档一行明细（`doc_id`、格式、策略、父块/子块数、已索引数、状态 ✅/❌），
以及**被跳过的文件清单**（不支持的格式会如实列出，不会假装处理过）。

**方式二：命令行摄入整个目录**（等价，口径完全一致）

```bat
cd /d F:\knowledge-fabric\services\ingest
python -m kf_ingest.cli --path "E:\Users\OMEN\Desktop\文档" --tenant demo --kb batch --dry-run
python -m kf_ingest.cli --path "E:\Users\OMEN\Desktop\文档" --tenant demo --kb batch
python -m kf_ingest.cli --path "E:\Users\OMEN\Desktop\文档" --tenant demo --kb batch --recursive --match 灯
```

| 参数 | 作用 |
|---|---|
| `--path` | 文件**或目录**（给目录即批量模式） |
| `--tenant` / `--kb` | 落到哪个租户 / 库（与界面同一含义） |
| `--dry-run` | 只跑到切片、不落库（**建议先跑一次看报告**） |
| `--recursive` | 递归子目录（默认只扫顶层） |
| `--match 灯` | 文件名包含该子串才处理 |
| `--json` | 输出机读摘要 |
| `--graph` / `--acl` / `--strategy` | 同界面同名选项 |

**几条必须知道的行为**：

- **支持格式**：`.pdf`、`.md` / `.markdown` / `.mdown`。
  `.docx / .doc / .txt / .jpg / .sql` 等会被**跳过**，并在报告里**如实列出**——
  混合格式的目录目前需要先把这些文件转成 PDF / Markdown。
- **`doc_id` 由文件名自动派生**（取不含后缀的文件名）。因此目录模式下**不允许**再用
  `--doc-id` 指定名称——多篇文档共用同一个 id 会互相覆盖，命令会直接拦下（退出码 2）。
  想让某文件用别的 id，就单独传那个文件（单文件模式可以 `--doc-id`）。
- **一篇失败不会中断整批**：会继续处理后面的文件，末尾汇总「成功 / 失败」；
  有失败时退出码为 `1`（全部成功为 `0`，参数错为 `2`）。
- **隐藏文件与 Office 临时文件**（`~$…`）不会被处理。

## 5. 检索结果怎么读

请求成功后，页面自上而下分三块。

### 5.1 概要行

`耗时 · 档位 · 通道(sparse:5 dense:3 …) · 融合(rrf/weighted) · 重排(已启用/未启用) ·
重排耗时 · 查询语言 · 集合名 · 上下文 token`

**集合名**形如 `kf_acme_demo`（= `kf_<租户>_<库>`）。它和你填的租户/库必须一致，
否则必然检索不到。

### 5.2 提示行（降级 / 提示）

- `按档位拒答：最高分低于答案可达阈值` —— 证据分太低，系统按设计拒绝回答。
- `降级/提示：重排不可用；复用信号…` —— 重排端点没起，链路自动降级，**不影响可用性**。
- `Agentic 轮数 1·停止 no_generator` —— 没有生成端点时**只跑 1 轮并如实标注**，不伪造多轮。
- `Graph 命中实体 …·社区 …·… 跳` / `Graph 未启用`
- `结构化命中 N` / `结构化跳过：…`

### 5.3 证据卡片（核心）

每条证据的头部标签：

| 标签 | 含义 |
|---|---|
| `#1 0.4832` | 排序序号 + 该条得分 |
| `第 4 页` | 在原文中的页码 |
| `text` / `table` / `code` | 块类型（表格、代码是**原子块**，不会被切开） |
| `sparse 通道` / `dense 通道` | 这条是被哪个召回通道命中的 |
| `父块回填` | 该条内容由更大的**父块**回填（保留上下文），但**字符偏移仍属于实际命中的子块** |

正文下方给出**可核实的定位信息**：

- **字符区间**：如 `字符 0–945`，配合来源文件可精确定位到原文片段（一键还原 / 高亮）。
- **来源**：原始文件路径（`source_uri`）。

> 「父块回填」与「字符区间」的语义**故意分开**：回填只替换正文内容，偏移永远标注
> 在真正命中的子块上。这样你点击引用时不会跳到错误位置。

## 6. 一次完整的测试演练（照着做即可）

目标：上传一份 PDF → 建库 → 提问 → 确认证据可核实。

1. **起服务**：按 §2 起好 postgres / qdrant / 三个服务，终端 C 等到日志出现
   `Laya checkpoint 就绪`。
2. **开控制台**：双击 `console\index.html`。
3. **先预览切片**：
   - 拖入任意一份中文 PDF；
   - `doc_id` 填 `test_v1`，`version` = `1`，`lang` = `zh`；
   - **勾上 `dry-run`**；点「上传并摄入」；
   - 看切片统计：块数、平均 token、使用了哪个策略。
4. **正式摄入**：
   - 取消勾选 `dry-run`（`graph` 先不勾）；
   - 点「上传并摄入」；
   - 结果里应看到 **Qdrant 写入点数 > 0**、**Postgres 写入行数 > 0**。
5. **确认入库**：切到「文档库」页签，点「刷新」——应看到 `test_v1`，
   `active_chunks` 与你刚写入的块数一致。
6. **提问**：切到「检索问答」页签，填一个**文档里确实有答案**的问题
   （先随手翻两页 PDF，挑一句事实性内容来问，例如某条款、某参数），档位留
   `hybrid_rerank`，点「检索」。
7. **核实证据**：
   - 看证据卡片的 `第 X 页` 是否与原文相符；
   - 用 `字符 起始–结束` 与来源文件定位原文，逐字比对；
   - 若问题答案就是文档里的明文，证据正文里应能找到它。
8. **试降级场景**：把检索服务停掉再点「检索」，页面应显示「检索失败，请确认
   kf-retrieve 已启动」，而**不是**白屏或卡死。重启服务后恢复。
9. **试权限（可选）**：重新摄入一份文档，`acl` 填 `user:alice`；然后在检索页
   `principal` 留空检索一次（能看到），再填 `user:bob` 检索一次（应看不到该文档的块）。

## 7. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 控制台状态灯是灰的（未连接） | 对应服务没起，或地址填错。按 §2 起服务并点「检测连接」。 |
| 上传成功但「文档库」里没有 | 多半是**租户/库**与摄入时不一致；集合名形如 `kf_<tenant>_<kb>`，两边必须一致。 |
| 检索「没有召回任何证据」 | ① 文档没摄入成功（回文档库看 `active_chunks`）；② 租户/库不一致；③ 提问用词与文档差异太大——换个更贴近原文的问法。 |
| 检索很慢（数秒） | 正常。检索阶段含召回 + 融合 + （若起了 TEI）重排；决策阶段 CPU 上 Laya 单条 0.9~5.0s。 |
| 提示 `降级/提示：重排不可用` | TEI 重排端点（默认 `localhost:8081`）没起。链路自动跳过重排，仍返回证据；要启用重排需 `docker compose up -d tei-rerank`。 |
| 提示 `结构化跳过` / `Graph 未启用` | 该档位 / 该库未开启对应通道，属正常提示，不代表出错。 |
| 上传 Markdown 后证据显示 `第 0 页` | Markdown 无分页，页码恒为 `0`，属如实标注（摘要里会有 `no_page_layout` 警告）。定位请看**字符区间 + 来源文件**。 |
| 目录批量摄入报告里「跳过 N 个」 | 那些文件后缀不受支持（如 `.docx / .txt / .jpg`）。报告会列出文件名，属如实记录，不是失败。 |
| 目录批量摄入提示「目录模式下不能指定 --doc-id」 | 命令行批量模式不允许自定 `doc_id`（由文件名派生，防止互相覆盖）。改用 `--match` 缩范围，或单独传那个文件。 |
| 决策服务 `/health` 显示 `mode=heuristic-fallback` | Laya 权重没加载成功。看同返回里的 `load_error` 与 `laya_checkpoint_errors`；确认 `LAYA_CACHE_DIR` 指向含 `hub/` 的缓存根。 |
| 机器重启后配置丢失 | `.env` 与终端里的 `set` 都是环境变量，重启终端需重新 `set`（见 §2）。 |

## 8. 当前能力边界（如实说明）

- **决策（Laya）**：权重已真机加载（`mode=laya`），但该 checkpoint 的**置信度未校准**，
  档位判定质量有限——真机复测 5 条查询中 1 条判对且被采纳、3 条回退安全档、
  1 条错判被采纳。系统对低置信**一律回退安全档 `hybrid_rerank`**，行为安全合规，
  但「Laya 参与决策」目前只算**部分有效**。详见 [README.md](../README.md)「已知缺口」。
- **TEI 嵌入 / 重排、OpenSearch、vLLM 生成端点**：都是**可选依赖**。缺失时链路
  **降级不中断**，只在 trace 的 `notes` 里如实记一条——不会假装跑过。
- **网关（8000）**：REST + MCP 双形态（需自行构建 Rust gateway），本手册的控制台
  走的是**摄入 8083 + 检索 8082**，不依赖网关。

## 9. 命令行等价操作（不想用界面时）

```bat
curl -s http://127.0.0.1:8083/health
curl -s http://127.0.0.1:8082/health
curl -s http://127.0.0.1:8090/health
```

**目录批量摄入（HTTP 形态）**——`dir` 是**服务端本机路径**，不是上传的文件：

```bat
curl -s -X POST http://127.0.0.1:8083/v1/ingest-dir -H "content-type: application/json" -d "{\"dir\":\"E:\\Users\\OMEN\\Desktop\\文档\",\"tenant\":\"demo\",\"kb\":\"batch\",\"recursive\":false,\"dry_run\":true}"
```

**命令行摄入整个目录**（与界面等价，无需服务在跑）：

```bat
cd /d F:\knowledge-fabric\services\ingest
python -m kf_ingest.cli --path "E:\Users\OMEN\Desktop\文档" --tenant demo --kb batch --dry-run
```

> `/v1/ingest-dir` 让调用方指定**服务端要读取的目录**，因此只适合**本机 / 受信任内网**使用，
> 不要把这个端点暴露到公网。

决策接口返回里的 `threshold_basis`（`laya_top1_probability` / `confidence`）、
`threshold_value`、`fallback_used`、`mode` 四个字段，就是「这次档位为什么这么定」的
审计依据。
